# N-to-N Multi-App Data Sync Hub

**Date**: 2026-05-28  
**Objective**: Build a Master Data Management (MDM) hub using Databricks as a central sync point for disparate JSON-based SaaS apps (BeProduct, DTC, Miro, XTS, etc.)

---

## 1. Executive Summary

This plan outlines a **snapshot-based, change-detection sync framework** where Databricks acts as the hub for bidirectional sync with multiple applications:

**Architecture**:
- **Daily Pull (Inbound)**: Full snapshots from each app (BeProduct, DTC, Miro, XTS) → Databricks Delta tables
- **Transform (Hub)**: Normalize, deduplicate, massage data across app silos
- **Change Detection**: Compare snapshots to identify INSERT/UPDATE/DELETE (no CDC/webhooks)
- **Selective Push (Outbound)**: Push only changed records back to each app using app-specific APIs
- **Conflict Resolution**: Handle overlapping data ownership via lineage tracking and policies

**Benefits**:
- Works with any JSON API (no webhooks/CDC required)
- Single source of truth during transformation
- Each app's API contract handled independently
- Audit trail of all changes via snapshots
- Extensible to new data sources

### 2.1 System Flow

```
│                        DAILY SYNC CYCLE                          │
└──────────────────────────────────────────────────────────────────┘

DAY N
├─ 02:00 UTC: PULL PHASE (Inbound)
│  ├─ BeProduct API → raw.beproduct_styles_20260528_0200

   │  ├─ BeProduct: push changed styles via SDK
```

### 2.3 Change Detection Strategy (Snapshot Comparison)

Since no CDC/webhooks available, use **hash-based diffing**:

```
1. On Day N pull:  raw.dtc_requests_20260528_0200 (full snapshot)
2. On Day N+1 pull: raw.dtc_requests_20260529_0200 (new full snapshot)
3. Join on business_key (e.g., request_id, item_id)
4. Compare row_hash:
   - hash_new != hash_old  → UPDATE
   - hash_new exists, hash_old NULL → INSERT
   - hash_new NULL, hash_old exists → DELETE
5. Write to change_log table
```

### 2.4 App Connectors (Abstracting API Differences)

Each app gets a connector module defining:
- **Pull**: How to authenticate, paginate, normalize to common schema
- **Push**: Which fields are writable, API method (REST POST/PATCH/PUT, SDK call)
- **Conflict Resolution**: Ownership rules (who wins for overlapping fields?)

```
Connector Interface:
├── AppConnector (base class)
│   ├── pull(since_timestamp) → DataFrame
│   ├── push(records, change_type) → push_status
│   ├── get_field_schema() → {field_name: type, writable: bool, ...}
│   └── resolve_conflict(field, values_by_app) → winning_value
```

## 3. Change Detection & Tracking Mechanism

### 3.1 Snapshot-Based Diffing (No CDC Required)

Since no app provides webhooks/CDC, use **hash-based comparison**:

**Algorithm**:
```python
def detect_changes(prev_snapshot, curr_snapshot, business_key_cols):
    """
    Compare two snapshots (from consecutive days).
    Returns: DataFrame with change_type (INSERT, UPDATE, DELETE)
    """
    prev_hash = prev_snapshot \
        .select("*", F.hash(*all_cols).alias("row_hash"))
    curr_hash = curr_snapshot \
        .select("*", F.hash(*all_cols).alias("row_hash"))
    
    changes = prev_hash.join(curr_hash, on=business_key_cols, how="full_outer") \
        .withColumn("change_type", 
            when(col("row_hash_curr").isNull(), "DELETE")
            .when(col("row_hash_prev").isNull(), "INSERT")
            .when(col("row_hash_curr") != col("row_hash_prev"), "UPDATE")
            .otherwise("NOCHANGE"))
    
    return changes.filter(col("change_type") != "NOCHANGE")
```

**Tradeoffs**:
- ✅ Works without CDC/webhooks
- ✅ Full audit trail (all snapshots retained)
- ✅ No missed changes
- ❌ Can't detect sub-day changes (only daily)
- ❌ More storage (retain snapshots)

### 3.2 Change Tracking Table Schema

```sql
CREATE TABLE IF NOT EXISTS main.sync_hub.change_log (
    change_id STRING,                      -- UUID
    source_app STRING,                     -- "beproduct", "dtc", "miro", "xts"
    entity_type STRING,                    -- "style", "request", "board", "item"
    entity_id STRING,                      -- App's record ID
    business_key STRING,                   -- Dedup key (e.g., "style-001")
    change_type STRING,                    -- "INSERT", "UPDATE", "DELETE"
    changed_fields ARRAY<STRING>,          -- Which fields changed (for UPDATE)
    old_values MAP<STRING, STRING>,        -- Previous values
    new_values MAP<STRING, STRING>,        -- New values
    detected_at TIMESTAMP,                 -- When detected (end of daily pull)
    push_status STRING,                    -- "pending", "synced", "failed", "skipped"
    push_error STRING,                     -- Error message if failed
    pushed_at TIMESTAMP,                   -- When pushed
    curated_by STRING                      -- Which transformation touched this
);
```

### 3.3 Conflict Resolution Policy

When **multiple apps claim ownership** of a field:

```python
CONFLICT_RULES = {
    "item_name": {
        "owner": ["beproduct"],  # Only BP updates this
        "policy": "owner_wins"
    },
    "item_description": {
        "owner": ["dtc", "miro"],  # Both can write
        "policy": "last_write_wins"  # Or: "beproduct_wins", "manual_review"
    },
    "item_price": {
        "owner": ["xts"],  # Only XTS
        "policy": "owner_only"
    }
}
```

On conflict: either reject the change, flag for manual review, or apply policy.

### 3.4 Push Queue Pattern

Instead of pushing immediately, stage changes:

```
change_log (detected today) 
  → push_queue_beproduct (filtered + formatted for BP)
  → push_queue_dtc (filtered + formatted for DTC)
  → push_queue_miro (filtered + formatted for Miro)
  → push_queue_xts (filtered + formatted for XTS)
```

Each queue is **app-specific**: contains only fields that app supports + proper format.

### 4.2 AppConnector Base Class

```python
class AppConnector(ABC):
    """Base interface all connectors implement"""
    
    def __init__(self, api_key: str, api_url: str = None):
        self.api_key = api_key
        self.api_url = api_url
        self.session = self._create_session()
    
    @abstractmethod
    def pull(self, since_timestamp: datetime = None) -> DataFrame:
        """
        Fetch full snapshot of all entities from this app.
        
        Returns: PySpark DataFrame with columns:
        - app_id (String): Record ID in this app
        - entity_type (String): "style", "request", "board", "item"
        - entity_json (String): Full JSON blob
        - fetched_at (Timestamp): When pulled
        - last_modified (Timestamp): When last changed in source
        """
        pass
    
    @abstractmethod
    def push(self, records: DataFrame, change_type: str) -> DataFrame:
        """
        Push changed records back to this app.
        
        Args:
            records: Rows with change_type="INSERT"/"UPDATE"/"DELETE"
            change_type: "INSERT", "UPDATE", or "DELETE"
        
        Returns: Status DataFrame with columns:
        - app_id (String)
        - push_status (String): "success", "failed", "skipped"
        - error (String): Error message if failed
        """
        pass
    
    @abstractmethod
    def get_field_schema(self) -> dict:
        """
        Return field definitions for this app.
        
        Returns: {
            "field_name": {
                "type": "string|number|date|...",
                "writable": bool,
                "required": bool,
                "app_field_name": "actual_api_field_name"
            }
        }
        """
        pass
    
    def resolve_conflict(self, field_name: str, 
                        values_by_app: dict) -> tuple[str, str]:
        """
        Resolve conflicting values for same field from different apps.
        Returns: (winning_value, resolution_method)
        """
        policy = CONFLICT_RULES.get(field_name, {})
        owner = policy.get("owner", [self.app_name])
        
        if self.app_name in owner:
            return values_by_app.get(self.app_name), "owner_wins"
        else:
            # Escalate to manual review
            return None, "manual_review_required"
```

### 4.3 Pull Flow (Snapshot-Based)

```python
def pull_phase(spark, connectors: dict[str, AppConnector]):
    """
    Daily 02:00 UTC: Fetch full snapshots from all apps.
    Store in raw.{app}_snapshots table.
    """
    for app_name, connector in connectors.items():
        df = connector.pull(since_timestamp=None)  # Always full
        
        # Add metadata
        df = df.withColumn("snapshot_date", F.current_date()) \
               .withColumn("snapshot_time", F.current_timestamp())
        
        # Write to raw layer with partition by date
        table_name = f"main.sync_hub.raw_{app_name}_snapshots"
        df.write.format("delta") \
          .mode("append") \
          .partitionBy("snapshot_date") \
          .option("mergeSchema", "true") \
          .saveAsTable(table_name)
        
        logger.info(f"Pulled {df.count()} records from {app_name}")
```

### 4.4 Transform Flow (Change Detection & Dedup)

```python
def transform_phase(spark):
    """
    Daily 06:00 UTC: Detect changes, deduplicate, and stage for push.
    """
    # Step 1: Load today's and yesterday's snapshots
    today = F.current_date()
    yesterday = today - 1
    
    today_snap = spark.table("main.sync_hub.raw_dtc_snapshots") \
        .filter(col("snapshot_date") == today)
    yesterday_snap = spark.table("main.sync_hub.raw_dtc_snapshots") \
        .filter(col("snapshot_date") == yesterday)
    
    # Step 2: Detect changes using hash comparison
    changes = detect_changes(yesterday_snap, today_snap, 
                            business_key_cols=["entity_id"])
    
    # Step 3: Write to change_log
    changes.write.format("delta").mode("append") \
           .saveAsTable("main.sync_hub.change_log")
    
    # Step 4: Deduplicate across all apps
    curated = deduplicate_master(spark)  # See next section
    curated.write.format("delta").mode("overwrite") \
           .saveAsTable("main.sync_hub.master_items")
    
    # Step 5: Stage for push (format per each app's API)
    for app_name in ["beproduct", "dtc", "miro", "xts"]:
        queue = stage_for_push(curated, app_name)
        queue.write.format("delta").mode("overwrite") \
             .saveAsTable(f"main.sync_hub.push_queue_{app_name}")
```

### 4.5 Push Flow (Selective by App)

```python
def push_phase(spark, connectors: dict[str, AppConnector]):
    """
    Daily 10:00 UTC: Push changed records back to each app.
    """
    for app_name, connector in connectors.items():
        queue = spark.table(f"main.sync_hub.push_queue_{app_name}")
        
        for change_type in ["INSERT", "UPDATE", "DELETE"]:
            records = queue.filter(col("change_type") == change_type)
            
            # Push via connector
            results = connector.push(records, change_type)
            
            # Record status
            results.withColumn("app_name", F.lit(app_name)) \
                   .write.format("delta").mode("append") \
                   .saveAsTable("main.sync_hub.push_status_log")
```

## 4.6 Critical Data Transformation: Timezone Handling

**DTC Date Field Quirk** (from DTC developer):
- **GET (Pull)**: Date fields returned as ISO 8601 strings **in UTC**
- **POST/PATCH/PUT (Push)**: Date fields must be in **user's timezone** (from user profile)

**Implementation**:
```python
def transform_dates_for_dtc_push(records_df: DataFrame, user_timezone_map: dict) -> DataFrame:
    """
    Convert dates from UTC (in Databricks) to user's local timezone for DTC push.
    
    Args:
        records_df: Rows with date columns in UTC
        user_timezone_map: {user_id: "Asia/Hong_Kong", ...}
    
    Returns: Rows with dates in user's timezone
    """
    for user_id, tz in user_timezone_map.items():
        records_df = records_df.withColumn(
            "date_field",
            F.when(
                F.col("user_id") == user_id,
                F.from_utc_timestamp(F.col("date_field_utc"), tz)
            ).otherwise(F.col("date_field"))
        )
    return records_df
```

**Mapping**:
- Store user timezone preferences in Databricks (fetch from DTC user API or config)
- During transform phase: for each request/sheet, look up owner's timezone
- Before push: convert date columns from UTC → user's timezone
- **Test extensively**: UTC vs. user TZ mismatches are common bugs

This requirement adds a **data dictionary** as a prerequisite:

```
dtc_field_info table:
- field_name (String)
- field_type (String): "string", "number", "date", "checkbox", "dropdown", "lookup", "image", "attachment"
- format_hint (String): "ISO_8601_UTC" (for dates), "number_format", etc.
- push_timezone_required (Boolean): True only for date fields on push
```

### 6.1 AppConnector Implementation Example: DTC

```python
from connectors.base import AppConnector
from client.rest_client import RestClient

class DTCConnector(AppConnector):
    """DTC REST API Connector"""
    
    app_name = "dtc"
    
    def __init__(self, api_key: str):
        self.client = RestClient(
            base_url="https://dtc-api.lfapps.net/api",
            api_key=api_key,
            headers={"x-api-key": api_key}
        )
    
    def pull(self, since_timestamp=None) -> DataFrame:
        """Fetch all requests from DTC"""
        all_requests = []
        
        # Get all workspaces
        workspaces = self.client.get("/v1/workspaces")
        
        for ws in workspaces:
            # Get all documents in workspace
            docs = self.client.get(f"/v1/documents?workspacename={ws['name']}")
            
            for doc in docs:
                # Get all requests for this document
                reqs = self.client.post("/v1/requests", {
                    "workspaceName": ws['name'],
                    "filters": {"documentId": doc['id']}
                })
                
                for req in reqs:
                    # Get sheet data (rows)
                    sheet = self.client.get(
                        f"/v1/sheets/{req['sheetId']}/views/{req['defaultViewId']}"
                    )
                    
                    all_requests.append({
                        "app_id": req["id"],
                        "entity_type": "request",
                        "entity_json": json.dumps({
                            "request": req,
                            "sheet": sheet,
                            "document": doc,
                            "workspace": ws
                        }),
                        "last_modified": req.get("modified_at"),
                        "fetched_at": datetime.now(timezone.utc)
                    })
        
        return spark.createDataFrame(all_requests, schema=PULL_SCHEMA)
    
    def push(self, records: DataFrame, change_type: str) -> DataFrame:
        """Push changes to DTC"""
        results = []
        
        for row in records.collect():
            try:
                entity = json.loads(row["entity_json"])
                
                if change_type == "UPDATE":
                    # Use PATCH for partial updates
                    self.client.patch(
                        f"/v1/sheets/{entity['sheet']['id']}/views/{entity['sheet']['viewId']}",
                        {"sheetData": [entity['sheet_data']]}
                    )
                elif change_type == "DELETE":
                    # Delete rows via DELETE /rows endpoint
                    self.client.delete(
                        f"/v1/sheets/{entity['sheet']['id']}/views/{entity['sheet']['viewId']}/rows",
                        {"rowIndexes": [entity['row_index']]}
                    )
                
                results.append({
                    "app_id": row["app_id"],
                    "push_status": "success",
                    "error": None
                })
            except Exception as e:
                results.append({
                    "app_id": row["app_id"],
                    "push_status": "failed",
                    "error": str(e)
                })
```

### 6.2 Snapshot Diffing Example

```python
def detect_changes(prev_snapshot: DataFrame, 
                   curr_snapshot: DataFrame, 
                   business_key_cols: list) -> DataFrame:
    """
    Compare two snapshots and classify as INSERT/UPDATE/DELETE.
    Uses row hash to detect changes.
    """
    # Add row hash
    prev_with_hash = prev_snapshot \
        .select("*", F.hash(F.col("*")).alias("row_hash")) \
        .select("*")
    
    curr_with_hash = curr_snapshot \
        .select("*", F.hash(F.col("*")).alias("row_hash")) \
        .select("*")
    
    # Full outer join on business key
    joined = prev_with_hash.alias("prev") \
        .join(
            curr_with_hash.alias("curr"),
            on=business_key_cols,
            how="full_outer"
        )
    
    # Classify changes
    changes = joined.select(
        F.coalesce(F.col("prev.app_id"), F.col("curr.app_id")).alias("app_id"),
        F.coalesce(F.col("prev.entity_id"), F.col("curr.entity_id")).alias("entity_id"),
        F.when(F.col("prev.row_hash").isNull(), F.lit("INSERT"))
         .when(F.col("curr.row_hash").isNull(), F.lit("DELETE"))
         .when(F.col("prev.row_hash") != F.col("curr.row_hash"), F.lit("UPDATE"))
         .otherwise(F.lit("NOCHANGE"))
         .alias("change_type"),
        F.col("curr.*").alias("new_values"),
        F.col("prev.*").alias("old_values")
    )
    
    return changes.filter(F.col("change_type") != "NOCHANGE")
```

### 6.3 Deduplication & Conflict Resolution

```python
def deduplicate_master(spark: SparkSession, 
                       conflict_rules: dict) -> DataFrame:
    """
    Merge records across all apps into single master table.
    Resolve conflicts based on ownership policies.
    """
    master = None
    
    for app_name in ["beproduct", "dtc", "miro", "xts"]:
        app_data = spark.table(f"main.sync_hub.raw_{app_name}_snapshots") \
            .filter(F.col("snapshot_date") == F.current_date()) \
            .select("app_id", "entity_json", F.lit(app_name).alias("source_app"))
        
        if master is None:
            master = app_data
        else:
            master = master.union(app_data)
    
    # Group by business key and resolve conflicts
    result = master.groupBy("business_key").applyInPandas(
        lambda df: resolve_conflicts_for_record(df, conflict_rules),
        schema=MASTER_SCHEMA
    )
    
    return result

def resolve_conflicts_for_record(record_df, rules):
    """Resolve conflicts for a single record (Pandas UDF)"""
    values_by_app = {}
    for _, row in record_df.iterrows():
        values_by_app[row['source_app']] = json.loads(row['entity_json'])
    
    resolved = {}
    for field_name in get_all_fields(record_df):
        field_rules = rules.get(field_name, {})
        owner = field_rules.get("owner", list(values_by_app.keys())[0])
        policy = field_rules.get("policy", "owner_wins")
        
        if policy == "owner_wins" and owner in values_by_app:
            resolved[field_name] = values_by_app[owner].get(field_name)
        elif policy == "last_write_wins":
            # Use timestamp to determine winner
            latest = max(values_by_app.items(), 
                        key=lambda x: x[1].get("last_modified", ""))
            resolved[field_name] = latest[1].get(field_name)
    
    return resolved
```

## 7. Important Considerations & Limitations

### 7.1 Snapshot-Based Sync Tradeoffs

| Aspect | Advantage | Disadvantage | Mitigation |
|--------|-----------|--------------|-----------|
| **Full daily pull** | No missed changes, audit trail | Can't detect intra-day changes | Accept daily granularity |
| **Hash-based diffing** | Works without CDC/webhooks | Doesn't identify WHICH fields changed | Store old/new values for detailed diffs |
| **Push staging** | Decouples changes from push logic | Extra storage (push_queue tables) | Clean up after successful push |
| **Batch push** | Efficient (multiple records per call) | Risk of partial failure (some rows succeed, some fail) | Implement row-level tracking in push_status_log |

### 7.2 API-Specific Limitations

**BeProduct SDK**:
- No "fetch all since timestamp" - need to implement manual pagination
- Colorways and sizes are nested structures - flatten in Databricks

**DTC REST API**:
- Amendment logs don't include field-level change detail - only timestamps
- PUT requires entire sheet (can't do selective row updates) - use PATCH instead
- Attachment max 50MB - validate before push

**Miro API**:
- Real-time sync not available (REST only, no webhooks in free tier)
- Board.items can be large - paginate
- Authentication: OAuth2 (not API key) - handle token refresh

**XTS API** (assumed):
- Likely SOAP or older REST (check actual API)
- May have different field naming conventions
- Need to research rate limits

### 7.6 Change Detection Edge Cases

**Scenario**: Databricks UPDATE + same change in source app on same day

**Expected**: Detect as UPDATE, push works because we have latest values

**Actual**: Works if push happens after transform (10:00 UTC after 06:00 transform)

**Risk**: If app updates at 09:00 UTC (1 hour before push), we'll push stale data

**Mitigation**: 
- Make pull window longer (pull at 23:00 previous day, transform at 06:00, push at 10:00)
- Or: Accept that some changes from source app might be overwritten
- Or: Add "source app wins" rule for same-day conflicts
